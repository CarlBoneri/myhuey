# UX Reorganisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-cut the web UI into Home (control), room workbench (use), Studio (build), Scenes, and Settings, per the spec.

**Architecture:** The change is front-end only.
- New routes, with legacy redirects in `lib/router.ts`.
- Pure helpers (`roomSummary`, `traceHint`, quick-mode storage) live in `lib/` with vitest tests.
- Views are recomposed from existing components:
  - HomeView is rewritten.
  - RoomView splits into `RoomWorkbench` (new) and `RoomDesigner` (the renamed RoomView).
  - PlanView becomes Studio.
  - LightsView becomes a section of Settings.

**Tech Stack:** React 19, zustand, TypeScript, Vite, vitest (node env).

**Spec:** docs/superpowers/specs/2026-11-15-ux-reorg-design.md

## Global Constraints

- No backend changes. Home and the ⋮ menu send every call Active-only (no `X-Myhuey-Layout` header).
- Old hashes keep working:

  | Old hash | Goes to |
  |----------|---------|
  | `#/plan` | studio |
  | `#/plan/<room>` | studio focus |
  | `#/room/<room>/photo` | designer photo |
  | `#/lights` | settings lights |

- The rail has four tabs, in this order: Home, Studio, Scenes, Settings.
- The quick-mode storage key is `myhuey.quickMode`, default `code`; storage access is wrapped in try/catch.
- Styles use the existing CSS tokens only, so light and dark both work.
- No network at runtime beyond the local server.
- No AI attribution in commits.
- Verification gate after each task: `cd frontend && npx vitest run && npm run typecheck && npm run build`, all green.

## Review Focus

1. **A sandbox is open and the user taps a ⋮ suggestion on Home.** It must hit the Active layout's room, not the sandbox's.
2. **A room name with spaces or a slash appears in a route.** It must round-trip through `href` and `parseRoute`.
3. **The ⋮ menu is opened for a room with no lights placed.** It shows a hint, not an error toast.
4. **Renaming a room in the designer.** The URL follows the new name and stays in the designer.
5. **A trace click on a leaking spot.** It raises no toast, and the hint explains why.
