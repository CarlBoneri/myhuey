# Saved Layouts, Theme, and Room Fill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named layouts (one Active, the rest sandboxes) chosen per request by `X-Myhuey-Layout` / `--layout`, plus an app theme toggle (dark/light/system) and see-through room shapes on the floor plan.

**Architecture:** The Active layout's home data stays in the `config` document; every other layout is a record in storage (`layout:<id>` row in SQLite, `<stem>.layout-<id>.json` file for JSON storage). A `ContextVar` holds the open layout ID; `HueRoomService._load/_save` route home data (`rooms`, `scenes`, `home`) to the record while keeping `bridge`/`preferences` global. A pure ASGI middleware sets the variable from the header; the CLI sets it from `--layout`. The web client adds the header unless a call is marked Active-only (the home screen's room list, power, and dimmers).

**Tech Stack:** Python 3.11, FastAPI, sqlite3, argparse, pytest; React 19, zustand, TypeScript, Vite, vitest (node environment: pure-function tests only).

**Spec:** `docs/superpowers/specs/2026-11-15-layouts-design.md` (including "Added during the build")

## Global Constraints

- Global keys never copied into layouts: `bridge`, `preferences`, `schema_version`. Per-layout keys: `rooms`, `scenes`, `home`.
- `config.layout = {"id", "name"}`; a document without it gets `{"id": <new>, "name": "My home"}` on first use.
- Record contents: `{id, name, created, updated, schema_version, rooms, scenes, home}`.
- Layout names: 1–60 characters after trimming, unique case-insensitively; default `"Layout N"`.
- Unknown layout ID → HTTP 404 with detail `"That layout no longer exists"`.
- The Active layout can't be deleted.
- `API_REVISION` (server) and `API_VERSION` (`frontend/src/api.ts`) both become 5.
- Preference `theme`: default `"dark"`, allowed `("dark", "light", "system")`.
- `HomePlan.room_opacity`: float 0–1, default 0.4.
- No network at runtime; no new dependencies.
- Commits: plain `feat:`/`fix:`/`test:` messages, **no Co-Authored-By or any AI attribution**.
- Real-light checks only in the Office room, restoring its state afterwards; browser checks on a copy of the database on a second server port.

## Review Focus

1. **The open sandbox is deleted in another tab.** The next call 404s with "That layout no longer exists". The client should fall back to Active, not get stuck. Test: Task 6, `isMissingLayout`.
2. **Renaming to an existing name in a different case** ("my home" when "My home" is Active) is refused. Test: Task 3, `test_names_are_unique_ignoring_case`.
3. **A photo uploaded in a sandbox survives a prune run from the Active context.** Test: Task 3, `test_prune_keeps_images_only_a_sandbox_uses`.
4. **Requests with and without the header on the same server don't bleed into each other.** Test: Task 4, `test_header_does_not_leak_into_next_request`.
5. **JSON storage (`--db x.json`) supports every layout operation, including activate.** Task 1's tests are parametrized over `.db` and `.json`.

**Interfaces:**
- Produces (all take `path: str | Path | None`, default `DEFAULT_STORAGE_PATH`):
  - `load_layout(layout_id: str, path) -> dict | None`
  - `save_layout(record: dict, path) -> None`: writes `record["id"]`. JSON: temp file + `os.replace`, chmod 0o600.

SQLite: one connection, one transaction (`with connection:`). JSON: write `old_record` first, then config via temp + `os.replace`, then delete the new record's file. A crash leaves a duplicate, never a loss.

**Interfaces:**
- Produces in `layouts.py`:
  - `HOME_KEYS = ("rooms", "scenes", "home")`
  - `current_layout: ContextVar[str | None]` (default None)
  - `using_layout(layout_id: str | None) -> ContextManager`: sets and resets the var.
  - `ensure_identity(config: dict) -> bool`: adds `config["layout"] = {"id": new_id(), "name": "My home"}` when it's missing or invalid; returns True if it changed anything.
  - `clean_name(name: str) -> str`: trims; raises `ValueError("A layout name must be 1 to 60 characters")`.
- Service behaviour:
  - `_load()`:
    1. `load_config`. If `ensure_identity` changed it, save it.
    2. With no var, or the var equal to the Active ID, return config.
    3. Otherwise read the record (`LayoutNotFound` if it's missing). Build `{**config, schema_version: record.schema_version, **record's HOME_KEYS}` and pass it through `migrate()`. If it was upgraded, call `backup_layout(record, start)` and save the upgraded HOME_KEYS back to the record.
    4. Return the merged document, which has `schema_version` = CURRENT.
  - `_save(config)`:
    - In a sandbox: write the HOME_KEYS to the record (keep `id`/`name`/`created`, set `updated` = `time.time()`, `schema_version` = CURRENT). Then re-read the stored config, overwrite its non-HOME keys from `config`, and save that. The Active rooms are never touched.
    - Otherwise, as today.
- Add `self._active_id()`, which returns `load_config(...)["layout"]["id"]` after ensure_identity, for Task 3.

**Files:**

**Interfaces:**
- Produces on `HueRoomService`:

  - `new_layout(name: str | None = None, from_layout: str | None = None) -> dict`: returns the list entry. With `from_layout` None: empty rooms/scenes, `home = {"plan": deepcopy(active home.plan)}`.   - `resolve_layout(name_or_id: str) -> str`: an exact ID or a case-insensitive name match, else `LayoutNotFound`.
  - `referenced_images()`: collects from the stored config **and every record**, independent of the open layout. Keep the existing per-document collection as a helper.

**Interfaces:**
- Middleware: a pure ASGI class (not `BaseHTTPMiddleware`, so the ContextVar reaches sync endpoints through the same task). For HTTP paths starting `/api/` and not `/api/layouts`, it reads `x-myhuey-layout`:
  - If the header is empty or names the Active layout, it passes through with the var set to None.

  - `POST /api/layouts/{id}/activate` → the entry
  - `DELETE /api/layouts/{id}` → `{"deleted": id}`
